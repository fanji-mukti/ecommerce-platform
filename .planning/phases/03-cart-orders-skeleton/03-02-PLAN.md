<objective>
## Phase Goal

**As a** logged-in user, **I want to** build a cart with price-snapshotted line items and view my order history through an event-driven read model, **so that** I can review what I'm about to buy and track past orders before the real checkout flow lands in Phase 4.

*(Derived from ROADMAP.md's Phase 3 outcome-prose Goal line — see Plan 03-01's objective for the full note on why this isn't the strict mvp-phase template.)*

Build the Orders write-side domain: the `Order` aggregate that also serves as the first MassTransit saga state machine in this codebase (ADR-0005), enforcing `Pending -> Paid -> Fulfilled / Cancelled / Failed` transitions with real guard logic even though only `Pending` is reachable until Phase 4/5 wire the triggering events. Stands up `OrdersDbContext` (write table + read-model table + MassTransit outbox/inbox, per D-06/D-07), the two real domain event contracts, and applies the first EF Core migration for Orders.

Purpose: ORD-03 (state machine enforcement) plus the foundational schema/messaging plumbing Plan 03-03 (Orders API + read-model projector) depends on.
Output: `Order`/`OrderStateMachine`/`OrderReadModel`/`OrdersDbContext` compiled and migrated; `OrderCreated`/`OrderStatusChanged` Contracts; a passing state-machine transition-guard test suite.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-03-06 | Tampering | `dotnet ef database update` (Task 2) | medium | mitigate | Task 2 explicitly targets only the local Aspire/docker-compose Postgres instance, mirroring Catalog's already-applied migration process; no prod connection string exists yet (Phase 6 introduces Azure Postgres) |
