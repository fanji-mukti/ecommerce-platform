# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Per `03-CONTEXT.md`, FE-02 covers the `/cart` page only. ORD-01/ORD-02 (order history / detail) are API-only in Phase 3 — no `/orders` UI is built (order history page is deferred to V2 as FE-V2-01). This contract also covers wiring the existing disabled "Add to Cart — Coming Soon" button on `/product/:id` (the only entry point into the cart), since CART-01 requires an add action to exist somewhere in the UI.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Angular project (React/Next.js/Vite shadcn gate does not apply) |
| Preset | not applicable |
| Component library | Angular Material 20 (established Phase 2) — `mat-card`, `mat-icon-button`, `mat-chip`, `mat-button`, `mat-progress-bar`, `mat-spinner` |
| Theme | Prebuilt `indigo-pink.css` (M3-compatible), applied globally in `src/styles.scss`. Primary = Indigo `#3f51b5`, Accent = Pink `#ff4081`, Warn = Red `#f44336` (Material palette); error-state text in the existing codebase uses `#d32f2f` directly (Red 700) — reuse this exact value for consistency, do not introduce the Material warn token as a separate value. |
| Icon library | Angular Material Icons (`mat-icon`, ligature names e.g. `arrow_back`, `add`, `remove`, `delete`, `shopping_cart`) |
| Font | Roboto (Google Fonts, loaded in `src/styles.scss`), weights 400/500/700 available; Phase 3 uses only 400 and 500 |

Source: detected from `src/frontend/ecommerce-app/src/styles.scss`, `src/app/app.scss`, and Phase 2 catalog/product-detail components. Not re-asked — carried forward as-is.

**Visual hierarchy / focal point:** The line-item list is the primary focal point on `/cart` — it occupies the majority of the viewport and is read top-to-bottom first. The Order Summary panel is the secondary focal point, positioned to the side (desktop) or below the list (mobile), anchored by the grand total in Display size (24px/400) to draw the eye once line items are scanned. The disabled "Proceed to Checkout — Coming Soon" CTA sits at the bottom of the summary panel, intentionally de-emphasized (disabled state) since it is not the actionable element in Phase 3.

## Spacing Scale

Declared values (must be multiples of 4) — **already established** in `src/styles.scss` as CSS custom properties; reuse verbatim, do not redeclare:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (e.g. quantity stepper gap) |
| md | 16px | Default element spacing |
| lg | 24px | Section padding, spacing below headings |
| xl | 32px | Page padding, grid gaps (matches `.catalog-page` precedent) |
| 2xl | 48px | Empty/error state vertical padding |
| 3xl | 64px | Page-level spacing (not used yet, reserved) |

Exceptions:
- Quantity stepper icon buttons (`mat-icon-button`) must meet a **44×44px minimum touch target** (accessibility) even though Material's default rendered icon-button is 40×40px — apply `min-width: 44px; min-height: 44px;` on the stepper's icon buttons specifically. No other exceptions.

## Typography

Reuses Angular Material's typography baseline (`mat-typography` class applied to `<body>` in `index.html`, established Phase 2). Declared roles for Phase 3's new cart UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 14px | 500 | 1.4 |
| Heading | 20px | 500 | 1.2 |
| Display | 24px | 400 | 1.2 |

- **Display** — page title (`<h1>Your Cart</h1>`), matches `.catalog-page h1` precedent.
- **Heading** — line-item product names, summary panel title ("Order Summary").
- **Label** — prices, quantity values, chip text, button labels.
- **Body** — supporting copy (empty/error state descriptions).

Only 3 distinct sizes (14/20/24) and 2 distinct weights (400/500) — no 700 usage in Phase 3, consistent with existing codebase (700 is loaded but unused).

The existing "Add to Cart" button on `/product/:id` keeps its established `color="primary"` (indigo) styling from the Phase 2 scaffold — only its `disabled` state and "— Coming Soon" label are removed when wired to the real cart-add action; its color is unchanged.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (product detail → cart) | Button label: **"Add to Cart"** (removes `disabled` attribute and the "— Coming Soon" suffix from the existing button; keeps `color="primary"`) |
| Cart page title | **"Your Cart"** |
| Empty state heading | **"Your cart is empty"** |
| Empty state body | **"Add items from the catalog to get started."** + a `mat-button` link labeled **"Browse Catalog"** routing to `/catalog` (mirrors the existing "Back to Catalog" link pattern in `product-detail.component.html`) |
| Error state heading | **"Failed to load cart"** |
| Error state body | **"Something went wrong while loading your cart. Please refresh the page or try again."** + a `mat-raised-button color="primary"` labeled **"Retry"** — verbatim reuse of the `catalog-list.component.html` error-state pattern (same wording template, `{{ noun }}` swapped from "products" to "cart") |
| Summary panel title | **"Order Summary"** |
| Summary line label | **"{quantity} × {productName}"** with line total right-aligned (currency) |
| Grand total label | **"Total"** |
| Item count (cart title subtext, optional) | **"{n} item"** (singular) / **"{n} items"** (plural) — pluralize on `n !== 1` |
| Deferred checkout CTA (summary panel, disabled) | **"Proceed to Checkout — Coming Soon"** (`mat-raised-button color="primary" disabled`) — mirrors the exact "— Coming Soon" disabled-placeholder convention already established for "Add to Cart — Coming Soon" in Phase 2; signals checkout is not yet wired (Phase 4) without leaving the summary panel dead-ended |
| Destructive confirmation | **Remove line item**: no confirmation dialog. Immediate removal on click of a trash/`delete` `mat-icon-button` per line item (`aria-label="Remove {productName} from cart"`). Reversible (re-add via catalog), low-stakes — matches the "instant, no network-blocking modal" philosophy in CONTEXT.md D-09. |

## UI Considerations

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | cart line-item list (list-collection) | ✅ covered | Empty cart renders the documented "Your cart is empty" / "Add items from the catalog to get started." + "Browse Catalog" link (see Copywriting Contract) |
| loading | cart line-item list (list-collection) | ✅ covered | `mat-progress-bar mode="indeterminate"` shown while `GET /cart` is in flight — reuses exact `catalog-list.component.html` pattern |
| error | cart line-item list (list-collection) | ✅ covered | Documented "Failed to load cart" error-state + Retry button (see Copywriting Contract), reusing `.error-state` SCSS pattern (`text-align: center; padding: 48px 0;`) |
| populated | cart line-item list (list-collection) | ✅ covered | Typical volume (1–10 items) renders as stacked `mat-card` line items with quantity stepper + remove icon-button + line total, per CONTEXT D-10 |
| zero-one-many | cart line-item list (list-collection) | ✅ covered | Zero → empty state; one/many → same stacked-card layout; item-count subtext pluralizes ("1 item" / "N items") |
| overflow | cart line-item list (list-collection) | ✅ covered | No pagination — cart lists rely on native page scroll (carts are user-scoped, expected low item count, consistent with Redis-cart no-TTL design in D-03) |
| long-text | cart line-item product name (static-content, inside list-collection card) | 🧪 backstop | Product name snapshot (D-05) truncates to 2 lines via `-webkit-line-clamp: 2` with ellipsis — no explicit visual regression test exists yet; verify at UAT with a long seeded product name |
| long-text | Add to Cart / Remove button labels (interactive-control) | ⚠ dismissed | Static short fixed-string labels ("Add to Cart", trash icon), never user-supplied — no overflow risk |
| partial | order summary panel (static-content, computed from line items) | ✅ covered | Summary always derives from whatever line items are currently loaded — no partial/incomplete data state possible since totals are computed client-side from the same snapshot data as the line-item list (D-05) |
