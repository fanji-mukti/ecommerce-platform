<objective>
## Phase Goal

**As a** logged-in user, **I want to** build a cart with price-snapshotted line items and view my order history through an event-driven read model, **so that** I can review what I'm about to buy and track past orders before the real checkout flow lands in Phase 4.

*(Derived from ROADMAP.md's Phase 3 outcome-prose Goal line — see Plan 03-01's objective for the full note.)*

Complete the Orders vertical slice: wire the read-model projector consumer that asynchronously populates `OrderReadModel` from the domain events Plan 03-02's saga publishes, expose `GET /orders`, `GET /orders/{id}`, and the explicitly-marked demo-only `POST /orders/test-create-from-cart` test-trigger that snapshots a user's cart into a Pending order and clears it (D-01/D-02). After this plan, a real authenticated user (via curl/Postman) can trigger order creation from their cart and see it appear in their order history.

Purpose: ORD-01, ORD-02, ORD-04 (list/detail/CQRS-read), CART-04 (cart cleared after the Phase 3 stand-in "checkout").
Output: Working, auth-protected, IDOR-safe Orders read API backed by an asynchronously-populated read model; a functioning (demo-marked) cart-to-order test trigger.
</objective>

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Spoofing | OrdersEndpoints (all 3 routes) | high | mitigate | JwtBearer auth (Plan 03-02) + `.RequireAuthorization()` on every route |
| T-03-10 | Information Disclosure (IDOR) | GET /orders/{id} | high | mitigate | Returns 404 (never 403) whether the order doesn't exist or belongs to another user — no existence leak; GET /orders always filters `WHERE UserId == caller`; verified by Task 2's cross-user 404 test |
| T-03-11 | Spoofing / Repudiation | POST /orders/test-create-from-cart mistaken for real checkout | medium | mitigate | Explicit demo-only marker in both the XML doc comment and the JSON response body (P2 prohibition), so Phase 4 planning and portfolio reviewers cannot mistake it for production |
| T-03-12 | Tampering | Bearer token forwarded Orders -> Cart | low | accept | Internal Aspire-orchestrated network only, standard token-forwarding pattern; out of scope to add mTLS for a portfolio demo |
