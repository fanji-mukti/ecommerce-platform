# Phase 1 Plan 01: Contracts Library Summary

**One-liner:** IMessageEnvelope interface with 16 positional-record namespace stubs (8 Events.V1 + 8 Commands.V1) across all 8 services, plus standalone Contracts.sln for CI matrix.

## What Was Built

The Contracts class library is now populated with the compile-time contract that every ASB message in the system must implement. Three distinct deliverables were produced:

1. **IMessageEnvelope interface** (`ECommerce.Contracts` namespace) — defines the 4-property envelope (MessageId, CorrelationId, CausationId, OccurredAt) that all domain events and commands must carry.

2. **16 namespace placeholder records** — 8 Events.V1 and 8 Commands.V1, one per service (Catalog, Cart, Checkout, Orders, Identity, Payments, Fulfillment, Notifications). Each uses positional record syntax implementing IMessageEnvelope, locking the `ECommerce.{ServiceName}.{Events|Commands}.V1` namespace convention.

3. **Contracts.sln** — standalone solution file generated by `dotnet new sln --format sln` containing only Contracts.csproj, enabling the CI matrix to build this library independently without any service project dependency.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] .NET 10 CLI defaults to .slnx format instead of .sln**

- **Found during:** Task 3
- **Issue:** `dotnet new sln` in .NET 10 creates `Contracts.slnx` (the new XML solution format) by default, not `Contracts.sln` as specified in the plan.
- **Fix:** Removed the auto-created `.slnx` file, then re-ran `dotnet new sln --format sln` to produce the traditional `.sln` format. The `--format` flag is documented in `dotnet new sln --help` and is safe to use.
- **Impact:** None — the resulting `Contracts.sln` is the standard format expected by the plan and the CI matrix entry point.
- **Files modified:** `src/building-blocks/Contracts/Contracts.sln` (created in correct format)

## Known Stubs

The 16 placeholder records are intentional stubs by design. Each contains a `{ServiceName}ServiceReady` or `{ServiceName}CommandsPlaceholder` record whose only purpose is to lock the namespace and verify IMessageEnvelope compliance. No real domain events exist yet — those arrive in later phases:

| File | Stub Type | Resolved In |
|------|-----------|-------------|
| All 8 `Events/V1/Placeholder.cs` | Namespace placeholder record | Phase 2+ (real domain events per service) |
| All 8 `Commands/V1/Placeholder.cs` | Namespace placeholder record | Phase 2+ (real command types per service) |

These stubs do not prevent the plan's goal from being achieved — the goal is to lock namespaces and compile, which they accomplish.
