    The workflow must follow the exact pattern from PATTERNS.md Pattern 5:

    name: CI

    on block: push.branches [main] and pull_request.branches [main] (D-15)

    jobs.build:
      runs-on: ubuntu-latest
      strategy:
        fail-fast: false   ← LOAD-BEARING: without this, first failure cancels all 9 remaining jobs
        matrix:
          solution: (list all 10 entries — exact paths relative to repo root)
            - src/building-blocks/Contracts/Contracts.sln
            - src/ecommerce.AppHost/ecommerce.AppHost.sln
            - src/services/catalog/Catalog.sln
            - src/services/cart/Cart.sln
            - src/services/checkout/Checkout.sln
            - src/services/orders/Orders.sln
            - src/services/identity/Identity.sln
            - src/services/payments/Payments.sln
            - src/services/fulfillment/Fulfillment.sln
            - src/services/notifications/Notifications.sln

      steps:
        1. uses: actions/checkout@v4
        2. uses: actions/setup-dotnet@v4 with dotnet-version: '10.0.x'  ← '10.0.x' allows patch updates without file change
        3. name: Restore — run: dotnet restore ${{ matrix.solution }}
        4. name: Build — run: dotnet build ${{ matrix.solution }} --no-restore --configuration Release
        5. name: Test — run: dotnet test ${{ matrix.solution }} --no-build --configuration Release

    Security constraints for CI (T-04):
    - No secrets referenced in the workflow file (no env: SOME_SECRET: ${{ secrets.* }})
    - No checkout of external untrusted repos
    - actions/checkout@v4 and actions/setup-dotnet@v4 are GitHub first-party actions (not third-party)
    - Do NOT add --verbosity diagnostic or any flags that emit environment variables to logs

    Note: dotnet test with --no-build on solutions with no test projects exits 0. xUnit v3 "no tests found" is not an error. This is safe for Phase 1.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → source code | Checkout action pulls code; no secrets needed for Phase 1 |
| Third-party actions | Only GitHub first-party actions used (actions/checkout, actions/setup-dotnet) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | ci.yml — secrets in workflow | mitigate | Phase 1 CI has zero secrets. Acceptance criteria verify no ${{ secrets.* }} references in ci.yml. If secrets are needed in a later phase, use GitHub Environments with required reviewers. |
| T-04-02 | Tampering | Third-party GitHub Actions | mitigate | Only actions/checkout@v4 and actions/setup-dotnet@v4 are used — both GitHub first-party. No community actions with arbitrary runner access. |
| T-04-03 | Elevation of Privilege | dotnet test — test code execution in CI | accept | Phase 1 has no test projects. When test projects exist in Phase 2+, tests run in GitHub-hosted runner sandbox. Risk is minimal for an OSS portfolio repo. |
| T-04-SC | Tampering | NuGet restore in CI | accept | NuGet packages are restored from nuget.org with pinned versions from .csproj files (no floating versions). Supply chain risk is mitigated by exact version pinning established in Plans 01 and 02. |
</threat_model>
