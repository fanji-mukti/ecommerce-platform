<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AppHost → container runtime | AppHost launches ASB emulator and Postgres containers — requires Docker Desktop |
| Aspire-injected env vars → services | Connection strings for postgres/redis/serviceBus are injected as env vars, not hardcoded |
| aspire publish output → git | Generated docker-compose.yml may contain .env file with SA password — must NOT be committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | docker-compose.yml + .env generated by aspire publish | mitigate | Verify .gitignore includes ".env" before running aspire publish. Aspire adds this automatically but confirm before first commit. The .env file contains ASB emulator and Postgres SA passwords. |
| T-03-02 | Information Disclosure | ecommerce.AppHost/Program.cs | accept | Program.cs contains no secrets — all connection strings are Aspire-managed and injected at runtime. Acceptance criteria verify no hardcoded strings. |
| T-03-03 | Denial of Service | RunAsEmulator() pulling mcr.microsoft.com/azure-messaging/servicebus-emulator:latest | accept | Tag is "latest" (floating) by design for Phase 1. Phase 2+ can pin to a specific digest if supply-chain policy requires it. Low risk for local dev. |
| T-03-SC | Tampering | NuGet package installs (4 Aspire.Hosting.* packages) | accept | All packages are [ASSUMED-APPROVED] per RESEARCH.md Package Legitimacy Audit (Microsoft first-party). No checkpoint needed. |
