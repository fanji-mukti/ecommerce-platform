<objective>
Create the YARP gateway as a new 9th service, wire it into the Aspire AppHost as the 10th resource, and add it to the CI matrix. The gateway routes /api/catalog/** and /api/identity/** to the correct downstream services using Aspire service discovery, forwarding the Authorization header without JWT validation.

Purpose: The gateway is the single entry point for Angular API calls. Without it, Angular would need to know the port of each backend service individually. YARP + Aspire service discovery allows route-based forwarding using logical service names resolved at runtime (per D-06 through D-09).

Output: Gateway.sln, ECommerce.Gateway.API project with YARP config, Gateway test project scaffold, AppHost updated with gateway reference, CI matrix updated with Gateway.sln.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Gateway (YARP) | All inbound API requests cross here; gateway does not validate JWT — trusts downstream services to do so |
| Gateway → downstream services | Internal Aspire service mesh — trusted network (localhost in dev, Container Apps VNet in prod) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05-01 | Elevation of Privilege | Gateway accidentally validates JWTs (misconfig) | mitigate | Program.cs must NOT contain AddAuthentication or AddJwtBearer; JWT validation is exclusively on downstream services per D-08; verified by acceptance criteria |
| T-02-05-02 | Spoofing | YARP cluster destination uses wildcard hostname | mitigate | YARP destinations use Aspire logical service names ("http://identity" etc.) resolved by AddServiceDiscoveryDestinationResolver — no user-controlled destination URLs |
| T-02-05-03 | Information Disclosure | YARP forwarding Authorization header to wrong service | mitigate | Routes are prefix-matched (/api/identity/** → identity cluster, /api/catalog/** → catalog cluster) with explicit PathRemovePrefix transforms; no catch-all route forwarding to wrong service |
| T-02-05-04 | Tampering | Aspire logical name mismatch causing 503 responses | mitigate | Gateway appsettings cluster names ("identity", "catalog", "notifications") verified to match AppHost AddProject registration names; acceptance criteria checks the WithReference connections |
| T-02-05-SC | Tampering | NuGet package installs | mitigate | Yarp.ReverseProxy 2.3.0 and Microsoft.Extensions.ServiceDiscovery.Yarp 10.7.0 pre-audited in RESEARCH.md Package Legitimacy Audit (Microsoft-maintained packages) |
</threat_model>
