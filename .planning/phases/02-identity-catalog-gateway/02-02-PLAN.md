<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| POST /register | Untrusted user input crosses into UserManager |
| GET /me | Requires valid JWT — validate before exposing claims |
| GET /connect/authorize | Untrusted browser request — must check auth state before issuing auth code |
| Razor Pages login form | Browser-submitted credentials cross into SignInManager |
| CORS preflight (browser→Identity) | Angular origin must be explicitly allowlisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Spoofing | POST /register — mass assignment (role elevation) | mitigate | RegisterRequest maps only Email and Password; UserManager.CreateAsync never sets roles from user input; no roles assigned at registration |
| T-02-02-02 | Elevation of Privilege | Password brute force on login form | mitigate | Lockout.MaxFailedAccessAttempts=5 in AddIdentity options; lockoutOnFailure=true in PasswordSignInAsync |
| T-02-02-03 | Elevation of Privilege | PKCE without code verifier | mitigate | RequireProofKeyForCodeExchange() in OpenIddict server options enforces PKCE for all auth code grants |
| T-02-02-04 | Spoofing | Open redirect via redirect_uri | mitigate | OpenIddict validates redirect_uri against registered URIs (http://localhost:4200/callback only); no wildcard URIs in client registration |
| T-02-02-05 | Elevation of Privilege | Password below minimum length | mitigate | FluentValidation MinimumLength(8) on RegisterRequest.Password (ASVS V2 min length) |
| T-02-02-06 | Information Disclosure | Stack traces in error responses | mitigate | All endpoints use Results.Problem / Results.ValidationProblem — never raw exception messages |
| T-02-02-07 | Elevation of Privilege | CORS bypass (AllowAnyOrigin) | mitigate | WithOrigins("http://localhost:4200") explicitly — never AllowAnyOrigin() in combination with credentials |
| T-02-02-08 | Information Disclosure | JWT token in session storage (XSS risk) | accept | Accepted for Phase 2 local dev — no sensitive operations beyond catalog browse; Phase 6 can harden if needed |
| T-02-02-SC | Tampering | NuGet package installs | mitigate | All packages pre-audited in RESEARCH.md Package Legitimacy Audit; OpenIddict 7.5.0 and ASP.NET Core Identity 10.0.9 are established, verified packages |
</threat_model>
