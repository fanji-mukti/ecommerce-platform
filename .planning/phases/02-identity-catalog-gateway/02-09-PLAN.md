<objective>
Fix three test infrastructure gaps — all in test files only, no production code changes.

Gap 3: CatalogWebApplicationFactory does not remove DbInitializer from the test host. DbInitializer runs during WebApplicationFactory startup, migrates the DB, seeds 30 products, and calls IPublishEndpoint.Publish through the EF outbox interceptor, leaving the DB in a state that conflicts with Given_CatalogHasProducts. Fix: add services.RemoveAll<DbInitializer>() to ConfigureServices; also remove AddEntityFrameworkOutbox from the in-memory MassTransit test registration (outbox is only meaningful with a real ASB transport).

Gap 4: CatalogSeededInboxDeduplicationSteps.When_SameMessagePublishedTwice publishes the same message object twice without setting ctx.MessageId on either publish call. MassTransit generates a fresh Guid transport MessageId per Publish call, so the inbox stores two rows. Fix: pass ctx => ctx.MessageId = messageId on both Bus.Publish calls, matching CatalogSeededConsumerSteps.

Gap 6: CatalogSeededConsumerSteps.Given_HarnessWithInMemoryTransport does not register NotificationsDbContext in DI. When MassTransit resolves CatalogSeededConsumer for each message, it fails with InvalidOperationException. Fix: add services.AddDbContext<NotificationsDbContext>(o => o.UseInMemoryDatabase("notifications-test")) to the test DI setup — the consumer calls db.SaveChangesAsync() and needs a resolvable DbContext.

Purpose: All three gaps cause test suite failures that mask real issues and reduce confidence in the test harness.
Output: Three corrected test step files; all affected test classes pass.
</objective>
