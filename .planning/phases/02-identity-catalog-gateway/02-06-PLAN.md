## Phase Goal

**As a** shopper, **I want to** register, log in, and browse a product catalog through a web interface, **so that** I can discover and view products without needing direct access to backend APIs.

<objective>
Scaffold the Angular 20 frontend with Angular Material 20, implement the five routes (/catalog, /product/:id, /login, /register, /callback), wire OIDC authentication via angular-auth-oidc-client, and configure the dev proxy to route /api/* through the YARP gateway.

Purpose: Delivers FE-01 (catalog and product detail browsing) and FE-04 (registration and PKCE login). This is the user-facing vertical slice — it ties together the Identity service (PKCE login), Catalog service (product API), and YARP gateway (routing) into a single end-to-end working demo.

Output: Angular 20 app at src/frontend/ecommerce-app/ with zoneless standalone components, Angular Material 20 theming, signal-based state, OIDC authentication configured, and a working dev proxy pointing to the YARP gateway.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Angular SPA → YARP gateway | All API calls cross here via /api proxy |
| Angular SPA → Identity service | OIDC redirect flows go directly to localhost:5005 (not through YARP) |
| Session storage (browser) | JWT access token stored here — accessible by same-origin JS only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06-01 | Information Disclosure | JWT in session storage (XSS risk) | accept | Accepted for Phase 2 — catalog browse has low sensitivity; OIDC + PKCE is correct; no HttpOnly cookie option without BFF pattern; Phase 6 can revisit |
| T-02-06-02 | Elevation of Privilege | RegisterComponent sending additional fields (mass assignment) | mitigate | RegisterComponent POSTs only email and password fields — no role, isAdmin, or other fields in the request body |
| T-02-06-03 | Spoofing | proxy.conf.json accidentally proxying /connect OIDC endpoints to gateway | mitigate | proxy.conf.json only proxies /api — OIDC flows (/connect, /.well-known) hit Identity directly; accepted per D-19 design; verified by acceptance criteria (authority=localhost:5005 not in proxy) |
| T-02-06-04 | Tampering | Angular calling wrong OIDC authority (through YARP) | mitigate | app.config.ts authority set to "http://localhost:5005" (Identity service direct URL) — not the gateway URL (localhost:5000); acceptance criteria checks this value |
| T-02-06-05 | Elevation of Privilege | Password field validation missing minLength | mitigate | RegisterComponent reactive form uses Validators.minLength(8) matching backend RegisterValidator; double-validation prevents short password submission |
| T-02-06-SC | Tampering | npm package installs | mitigate | angular-auth-oidc-client version pre-audited in RESEARCH.md Package Legitimacy Audit; peer dep verification step required before install (see action) |
