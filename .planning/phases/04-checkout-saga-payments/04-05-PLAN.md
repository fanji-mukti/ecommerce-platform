<objective>
Build Checkout.API as the thin, database-free public façade for the checkout saga: `POST /checkout` mints the checkoutId and synchronously hands off to Orders.API; `GET /checkout/{id}` polls Orders and maps its raw status vocabulary to the checkout-facing one (per ADR-0009, synthesizing "Started" from a 404 rather than persisting a new saga state); `POST /checkout/{id}/simulate-fulfillment-failure` is the demo-only CHK-04 trigger (D-01–D-03).

Purpose: This plan is the vertical-slice control point that wires the previously-independent Orders saga (04-02/04-03) and Payments service (04-04) into one user-reachable checkout flow, satisfying CHK-01/CHK-02/CHK-04.
Output: Fully wired Checkout.API service, new `ECommerce.Checkout.Tests` project.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Angular client → YARP Gateway → Checkout.API | Untrusted request bodies (`StartCheckoutRequest.SimulatePaymentFailure`), JWT-authenticated |
| Checkout.API → Orders.API (internal HTTP) | Bearer token forwarded, not attacker-reachable directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-04-12 | Information Disclosure | `GET /checkout/{id}` for another user's checkoutId | mitigate | Always returns `{status: "Started"}` for any 404 from Orders, regardless of cause (doesn't-exist-yet vs. not-owned vs. bogus id) — no distinguishing signal is ever returned, a stronger property than a bare 404 |
| T-04-13 | Elevation of Privilege | `POST /checkout/{id}/simulate-fulfillment-failure` against another user's order | mitigate | Ownership enforced via the SAME `GetStatusAsync` call (forwards the CALLER's own bearer token) that `GET /checkout/{id}` uses; Orders' own IDOR-safe 404 makes this impossible to bypass by guessing ids |
| T-04-14 | Denial of Service | Malicious enumeration of `GET /checkout/{id}` with random GUIDs | accept | Returns `{status: "Started"}` forever for any id that never resolves — a client-side nuisance for the prober, no data disclosure, no server-side amplification beyond one internal HTTP call per poll |
</threat_model>
