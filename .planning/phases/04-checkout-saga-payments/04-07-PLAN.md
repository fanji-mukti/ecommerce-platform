<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Azure Service Bus -> OrderStateMachine consumer | Redelivered / duplicate / racing saga events (broker at-least-once delivery) cross into the saga's state-machine consumer; a message legitimately arriving after the saga has already reached a terminal state is untrusted input relative to the saga's current state, not relative to the network. |
| Checkout.API demo trigger -> ASB -> OrderStateMachine | `POST /checkout/{id}/simulate-fulfillment-failure` is an authenticated, ownership-checked HTTP call, but its resulting `FulfillmentFailed` event races the eventually-consistent read model it read `Status` from — two rapid calls can both pass the `Status == "Paid"` check before the first event is consumed. |
| Angular checkout-page.component.ts -> Checkout.API | Client-side polling loop; an uncontrolled/leaked subscription is a client-side resource-exhaustion concern (duplicate concurrent HTTP polling loops), not a server trust-boundary crossing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07-01 | Denial of Service | `OrderStateMachine.During(Cancelled, ...)` | mitigate | Extend the catch-all to absorb `PaymentAuthorisedEvent`/`PaymentFailedEvent`/`FulfillmentFailedEvent`/`CheckoutTimeout.Received` (CR-01) — prevents a redelivered or racing message from repeatedly faulting the consumer and cycling through the retry/dead-letter path |
