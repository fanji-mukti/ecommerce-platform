## Spacing Scale

Declared values (must be multiples of 4) — **already defined in `src/styles.scss`, reuse verbatim, do not redeclare:**

| Token | Value | Usage |
|-------|-------|-------|
| xs (`--space-xs`) | 4px | Icon-to-label gaps within stepper step content |
| sm (`--space-sm`) | 8px | Compact spacing: checkbox-to-hint-text gap, chip padding |
| md (`--space-md`) | 16px | Default element spacing: card padding, form field gaps (matches `cart-line-item` card padding) |
| lg (`--space-lg`) | 24px | Section padding: heading-to-content gaps, card margin-bottom |
| xl (`--space-xl`) | 32px | Layout gaps: page padding (matches `cart-page`/`catalog-page` `padding: 32px`) |
| 2xl (`--space-2xl`) | 48px | Major section breaks: empty/error state vertical padding |
| 3xl (`--space-3xl`) | 64px | Not used this phase (no page-level marketing sections) |

Exceptions:
- 44×44px minimum touch target for any icon-only interactive control (matches existing `cart-line-item.component.html` pattern) — applies if the stepper renders clickable step icons.
- Mobile breakpoint at `max-width: 600px` reduces page padding to 16px and collapses any multi-column layout to single-column (matches `cart-page`/`catalog-page` existing `@media` blocks) — apply identically to `/checkout` and `/orders/:id`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 500 (medium) | 1.2 |
| Display | 28px | 500 (medium) | 1.2 |

Exactly 4 sizes, exactly 2 weights (400 regular / 500 medium — matches the Roboto weights already loaded; 700 is imported but reserved/unused this phase, do not introduce a third weight).

Usage mapping for this phase's new pages:
- **Display (28px/500):** the order grand total on `/orders/:id`'s status card (echoes `cart-page`'s existing `.summary-total { font-size: 24px }` pattern, bumped one step for the order-confirmation moment).
- **Heading (20px/500):** `mat-card-title`-equivalent section headings — "Checkout", "Order Summary", "Payment Status" — mirrors existing `h2 { margin-bottom: 16px }` usage in `cart-page`/`catalog-page`.
- **Body (16px/400):** stepper step labels, line-item text, failure-reason sentence (D-09), form/status paragraph text.
- **Label (14px/400):** hint text (D-10), timestamps, status chip text, checkbox label (D-11).

## Color

Reuses the existing Material Indigo/Pink prebuilt theme tokens already loaded project-wide — **no new hex values introduced this phase.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fafafa` | Page background (matches `body { background-color: #fafafa }` in `src/styles.scss`) |
| Secondary (30%) | `#ffffff` | Card surfaces: `mat-card` for the stepper container, order-summary card, status card |
| Accent (10%) | `#3f51b5` (Material `primary`/indigo) | **Reserved for exactly:** the Place Order button, the current/completed stepper step indicator, the "View Order" / navigation links, focus rings |
| Destructive/semantic | `#d32f2f` (Material `warn`/red, matches existing `.error-state h2 { color: #d32f2f }`) | **Reserved for exactly:** `Cancelled`/`Failed` status chip and heading text on `/orders/:id`, the generic polling-error state heading (reuses existing error-state pattern), no other use |

Accent reserved for: Place Order button, active/completed step icon in the stepper, "View Order"/"Browse Catalog" links, focus indicators. **Not** used for the demo toggle, hint text, or informational chips.

Note on existing inconsistency: `login`/`register`/`product-card` use `color="accent"` (pink `#ff4081`) for their primary CTAs elsewhere in the app, while `cart-page`/`product-detail` use `color="primary"` (indigo). This phase follows the **`cart-page` precedent** (`color="primary"`) since `/checkout`'s Place Order button is the direct, literal replacement of `cart-page`'s existing disabled `color="primary"` button — do not switch to accent/pink for this phase's new CTAs. Pink/`accent` is not used anywhere in this phase's new UI.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Place Order"** (cart-page's placeholder "Proceed to Checkout — Coming Soon" is replaced by this, enabled, on `POST /checkout` success it becomes disabled with a loading spinner until the 202 response returns) |
| Empty state heading | "Your cart is empty" (reuses `cart-page.component.html`'s exact existing empty-state copy — `/checkout` redirects to `/cart` if the cart is empty rather than rendering its own empty state, per the façade's server-side validation in RESEARCH.md) |
| Empty state body | "Add items from the catalog to get started." (verbatim reuse from `cart-page.component.html`) + "Browse Catalog" link |
| Error state (generic poll/load failure) | Heading: "Unable to load checkout status" — Body: "Something went wrong while checking your order. Please refresh the page or try again." + `mat-raised-button color="primary"` "Retry" (mirrors `cart-page`'s existing error-state shape exactly) |
| Terminal failure — payment declined (D-09) | "Payment declined" (exact locked copy from CONTEXT.md D-09) |
| Terminal failure — fulfillment failure (D-09) | "Fulfillment failed — order cancelled and refunded" (exact locked copy from CONTEXT.md D-09) |
| Terminal failure — timeout (CHK-05) | "Checkout timed out before payment completed" (matches the `FailureReason` string used server-side in RESEARCH.md's Pattern 1 code example — Angular must render this string verbatim, not reword it) |
| Demo hint text (D-10) | "Tip: cart totals ending in .99 simulate a payment failure." (exact locked copy from CONTEXT.md D-10) |
| Demo toggle label (D-11) | "Simulate payment failure" (exact locked copy from CONTEXT.md D-11) |
| Stepper step labels (D-06) | "Started" → "Awaiting Payment" → "Paid" (exact checkout-facing vocabulary from RESEARCH.md's state-mapping table — never render the raw saga `CurrentState` string like `Pending`) |
| Destructive confirmation | **None in this phase.** Place Order is a commit action, not destructive (no confirmation dialog). The demo toggle (D-11) is non-destructive and reversible before submission. `POST /checkout/{id}/simulate-fulfillment-failure` is API/test-only per D-02 (no Angular UI control, so no confirmation copy needed). Cart item removal (shipped in Phase 3) remains a direct action with no confirmation dialog — unchanged, not revisited this phase. |
