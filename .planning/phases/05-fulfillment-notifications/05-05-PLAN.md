<objective>
Give Notifications its first real business entity and its first authenticated HTTP endpoint. Three new stateless consumers (mirroring the existing `CatalogSeededConsumer` shape exactly) write a `NotificationEntry` row for each of `OrderStatusChanged{NewStatus="Paid"}`, `OrderShipped`, and `PaymentFailed`; `GET /notifications` exposes them JWT-scoped, IDOR-safe, mirroring `OrdersEndpoints`'s `GET /orders` pattern.

Purpose: Deliver NOT-01/NOT-02 — the in-app inbox that lets a user see the saga lifecycle events they participated in, without any synchronous cross-service lookup (D-03's UserId-on-event design pays off here).
Output: `NotificationEntry` entity + migration, three new consumers, `GET /notifications`, JWT auth wiring (Notifications currently has none), and a placeholder-sentinel fix to `Program.cs`'s MassTransit bus wiring so the new endpoint is testable via `WebApplicationFactory`.
</objective>

|-----------|----------|-----------|-------------|-------------------|
| T-05-08 | Information Disclosure (IDOR) | `GET /notifications` returning another user's inbox entries | mitigate | Query is scoped server-side by `GetUserId(ClaimsPrincipal)` derived from the validated JWT — never a client-supplied parameter; identical, already-tested pattern to `GET /orders` |

</threat_model>
